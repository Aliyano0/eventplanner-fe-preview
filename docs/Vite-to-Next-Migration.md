# Vite → Next.js 16 Migration

Part of [[00-Home]]. Evidence: [[Verification-Report]]. Open decisions: [[Follow-ups]].

The frontend was generated by Lovable as a React 18 + Vite 5 + React Router 6 + Tailwind 3 single-page app. It is
now a Next.js **16.3.8** App Router application with React 19, TypeScript strict mode and Tailwind v4 (the
stack in the PRD — [[PRD-Alignment]]). **Goal: every screen looks and behaves exactly as before.**

## File mapping

| Lovable (Vite) | Next.js |
| --- | --- |
| `index.html` | `src/app/layout.tsx` (+ `metadata`) |
| `src/main.tsx`, `src/App.tsx` | `src/app/layout.tsx`, `src/app/providers.tsx`, one `page.tsx` per route — [[Routing-Map]] |
| `src/pages/*.tsx` | `src/views/*.tsx` (see [[Architecture]] for why not `src/pages`) |
| `src/pages/Index.tsx` / `Dashboard.tsx` / `PlannerSetup.tsx` | `HomePage` / `DashboardPage` / `PlannerSetupPage` (renamed for consistency) |
| `src/pages/NotFound.tsx` | `src/app/not-found.tsx` |
| `src/index.css` | `src/app/globals.css` — [[Tailwind-v4-Compatibility]] |
| `public/favicon.ico` | `src/app/favicon.ico` (auto-linked) |
| `vite.config.ts`, `tsconfig.app.json`, `tsconfig.node.json` | `next.config.ts`, `tsconfig.json` |
| `eslint.config.js` | `eslint.config.mjs` |
| `tailwind.config.ts` | CSS-first `@theme` in `globals.css` |
| `vitest.config.ts` | `vitest.config.mts` |
| `src/App.css` (empty), `src/components/NavLink.tsx` (unused), `src/vite-env.d.ts` | deleted |
| `playwright*.ts`, `lovable-tagger` | deleted — [[Dependencies]] |

## Code changes

- `react-router-dom` → `next/link`, `next/navigation` ([[Routing-Map]]).
- `"use client"` where state/effects exist; Services, Vendors, Book, Manage Venue became Server Components
  ([[Server-vs-Client-Components]]).
- Hero image: `<img>` → `next/image` (`fill`, `priority`, `sizes="100vw"`), same box and `object-cover`.
  Remote Unsplash/venue images stay plain `<img>` (masonry layout depends on their natural height; documented
  with an ESLint comment).
- `localStorage` reads moved behind `useStoredValue` so server HTML = first client render
  ([[State-and-Storage]]). `BudgetPage` previously read `localStorage` inside a `useState` initialiser, which
  would have crashed server rendering.
- `TasksPage`: the `TaskCard` component was declared *inside* the page component (remounted on every render);
  hoisted to module scope with props. No visible change.
- Strict TypeScript: the Lovable config had `strict: false`; the code type-checks cleanly with `strict: true`.
- ShadCN kit: `"use client"` on hook-using files, `calendar.tsx` ported to react-day-picker v9, two empty
  interfaces replaced with type aliases, `use-mobile` rewritten with `useSyncExternalStore`.

## Intentional deviations (small, listed so nothing is a surprise)

| # | Change | Why | Visible effect |
| --- | --- | --- | --- |
| 1 | Navigation buttons became `<a>` links (`next/link`) | crawlable URLs, prefetching, open-in-new-tab; PRD F2/F7 | none — classes were adjusted (`w-fit`, `text-center`) so boxes and text align identically |
| 2 | HTTP **404** status for unknown URLs | the SPA returned 200 for everything | none on screen |
| 3 | Per-route `<title>` + real description/Open Graph basics | the old title was the placeholder "Lovable App"; OG image and `@Lovable` Twitter handle pointed at lovable.dev | browser tab titles |
| 4 | Numbers use `en-US` formatting (`formatNumber`) | the old `toLocaleString()` depended on each visitor's locale and would mismatch SSR | identical for `en-US`, `en-GB`, `en-PK`, `ur-PK` browsers; visitors with `en-IN` (lakh grouping), `de`, `fr`… now see `100,000` instead of their locale's style |
| 5 | Task deadlines format in UTC | `new Date("2026-04-25")` is UTC midnight; in timezones west of UTC the old UI showed *Apr 24* | identical for Pakistan/Europe/Asia; US visitors now see the authored day |
| 6 | Hero image is served by the Next image optimizer | performance (LCP, size) | ~6 anti-aliased pixels differ from the original JPEG |
| 7 | Dev-only Radix accessibility warnings no longer print in production | compiled out by Next | none (the underlying missing `DialogTitle`/`Description` still exists — [[Follow-ups]]) |
| 8 | `hover:` styles apply only on hover-capable devices | Tailwind v4 default | touch devices no longer keep a "stuck" hover after a tap — [[Tailwind-v4-Compatibility]] |
| 9 | Unused `QueryClientProvider` removed | PRD reads go through Server Components | none |

Everything else — layout, spacing, colours, fonts, animations, form behaviour, dialogs, routing, local storage —
was compared against the original and found identical ([[Verification-Report]]).

## Rollback

Nothing from the Lovable project was committed to git before this work (the repo only contained `LICENSE`), so a
full copy of the original Vite source was taken first and kept outside the repository. See [[Follow-ups]].
